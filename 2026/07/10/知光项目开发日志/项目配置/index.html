全局异常处理器

GlobalExceptionHandler.java

解释：这里使用@RestControllerAdvice相当于@ControllerAdvice + @ResponseBody

  • @ControllerAdvice：声明这个类是一个全局增强器，能拦截所有 @Controller（或 @RestController）中抛出的异常。
  • @ResponseBody：方法的返回值会直接序列化为 JSON 写入 HTTP 响应体，而不是跳转到视图页面。

所以这个类能捕获异常并返回 JSON 格式的错误信息。

处理业务异常

@ExceptionHandler(BusinessException.class)

  • 表示这个方法专门处理 BusinessException 类型的异常。
  • 当程序里任何地方抛出 BusinessException（通常是业务逻辑校验不通过时手动抛出），就会被这个方法拦截。

方法逻辑：

  1. 从异常对象里取出错误码（ex.getErrorCode().getCode()）和错误消息（ex.getMessage()），放进一个 Map 作为 JSON 响应体。

  2. ex.getErrorCode() 应该是自定义的 ErrorCode 枚举或类，内部预定义了一组“错误码 + 默认消息”，例如 1001 对应“用户不存在”。

  3. ex.getMessage() 通常是具体描述，比如“用户ID为123的用户不存在”。
    错误码和消息在下面

ResponseEntity.badRequest().body(body)

  • 返回 HTTP 400 状态码（Bad Request），并将上面的 Map 作为响应体。
  • 这告诉客户端：本次请求属于客户端参数或业务错误。

处理 @Valid 请求体校验失败

主要处理参数校验失败

@ExceptionHandler(MethodArgumentNotValidException.class)

  • 当你在 Controller 里使用 @Valid 注解校验请求体（比如 @RequestBody @Valid UserDto dto），而校验不通过时，Spring 就会抛出这个异常。

MethodArgumentNotValidException.class为java提供的。

方法逻辑：

  1. 提取第一个字段校验失败的错误信息。
    ex.getBindingResult().getFieldErrors() 会拿到所有字段错误的列表，这里用 findFirst() 取第一条，通过 FieldError::getDefaultMessage 获得你在注解里自定义的 message，如 @NotBlank(message = “用户名不能为空”) 中的“用户名不能为空”。
  2. 如果没有字段错误（极少情况），则用 ErrorCode.BAD_REQUEST 里的默认消息作为兜底。
  3. 组装统一响应体：code 用的是 ErrorCode.BAD_REQUEST 预先定义的错误码，message 则是上面取得的校验提示。
    同样返回 HTTP 400。

  • 简单来说，@Valid 的作用就是让 Spring 自动帮你检查前端传来的数据是否符合要求，不用再手写一堆 if-else 判断。

处理 @Validated 方法参数校验失败

@ExceptionHandler(ConstraintViolationException.class)

  • 这对应另一种参数校验方式：在 Controller 类上标注 @Validated，然后在方法参数上直接用校验注解（如 @NotBlank String name）。校验失败时抛出的是 ConstraintViolationException（注意它来自 javax.validation 或 jakarta.validation），跟上面的 MethodArgumentNotValidException 是不同的异常类型。

方法逻辑：

  1. 直接取异常的自带消息 ex.getMessage()，拼接成统一格式并返回 HTTP 400。
  2. ex.getMessage() 会包含类似 “addUser.arg0: 用户名不能为空” 的信息，虽然不如上面那样只取一条干净提示，但足够排查问题。

兜底处理所有未知异常

@ExceptionHandler(Exception.class)

  • 这是最宽泛的异常捕获，只要不是前面几种具体异常，都会落到这里。相当于一个“安全网”。

方法逻辑：

  1. 用 log.error 把异常详细信息记录到服务器日志，便于开发人员排查（前端不需要看到堆栈信息）。
  2. 返回固定错误码 “INTERNAL_ERROR” 和通用友好提示“服务异常，请稍后重试”。
  3. 状态码设置为 HTTP 500（服务器内部错误）。
