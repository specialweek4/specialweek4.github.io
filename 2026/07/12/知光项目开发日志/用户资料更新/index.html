个人资料局部更新 Request (DTO) ProfilePatchRequest.java

@Size

来源：jakarta.validation.constraints.Size

作用：约束字符串、集合、数组等类型的大小（长度或元素数量）。

参数：

  • min：最小长度（包含），默认 0
  • max：最大长度（包含），默认 Integer.MAX_VALUE
  • message：校验失败时的提示信息

应用于：

  • nickname：@Size(min = 1, max = 64, message = “昵称长度需在 1-64 之间”)
    要求昵称不能为空（min = 1）且不超过 64 个字符。
  • bio：@Size(max = 512, message = “个人描述长度不能超过 512”)
    未指定 min，默认允许空字符串，但不超过 512 个字符。
  • school：@Size(max = 128, message = “学校名称长度不能超过 128”)
    同样允许为空，但不超过 128 个字符。

@Pattern

来源：jakarta.validation.constraints.Pattern

作用：校验字符串是否匹配给定的正则表达式。

参数：

  1. regexp：正则表达式（Java 语法）
  2. flags：可选，Pattern.Flag 数组，用于调整匹配行为（如大小写不敏感）
  3. message：校验失败时的提示信息

应用于：

gender：@Pattern(regexp = "(?i)MALE|FEMALE|OTHER|UNKNOWN", message = "性别取值为 MALE/FEMALE/OTHER/UNKNOWN")

  • (?i) 是内嵌标志，表示不区分大小写。
  • 该正则要求输入完全等于 MALE、FEMALE、OTHER 或 UNKNOWN 之一（忽略大小写），例如 male、Female 均合法。

zgId：@Pattern(regexp = "^[a-zA-Z0-9_]{4,32}$", message = "知光号仅支持字母、数字、下划线，长度 4-32")

  • ^ 和 $ 表示全字符串匹配。
  • 只允许字母、数字、下划线，且长度必须在 4 到 32 之间（注意此处 Pattern 本身只控制内容格式，长度由正则内部限制，未单独使用 @Size）。

@PastOrPresent

来源：jakarta.validation.constraints.PastOrPresent

作用：约束日期/时间类型的值必须是过去或现在的时间点（即不能是未来的日期）。

参数：仅可选 message。

应用于：birthday：@PastOrPresent(message = “生日不能晚于今天”)
确保用户提供的生日不会是一个将来的日期。

个人资料业务接口 ProfileService.java

个人资料业务服务 ProfileServiceImpl.java

整体设计:

(1)getById

  1. 使用只读事务：通知数据库和持久层框架仅读取，可优化连接资源与脏检查。
  2. Optional 返回：明确表达“用户可能不存在”的语义，强制调用方进行判空处理，避免 NPE。此处未直接抛出异常，给予上层根据业务场景决定处理方式的灵活性。

(2)updateProfile

  1. 判断用户是否存在
  2. 判断请求种是否提交至少一个字段，否则属于”未提交任何更新字段”。
  3. 在提交更新知光号的前提下检验知光号是否唯一。
  4. 使用getUser将提交的字端存到user对像中，防止直接将前端传过来的DTO作为更新对象，导致数据库中的字段被null覆盖。
  5. 更新后回读，保证返回数据为最新快照

(3)updateAvatar

  1. 判断用户是否存在
  2. 仅更新头像URL
  3. 回读

个人资料接口 ProfileController.java

整体设计：

  1. 使用@Validated开启方法级别的校验
  2. 使用@RequiredArgsConstructor为三个 private final 字段，自动生成 public ProfileController(ProfileService, JwtService, OssStorageService) 构造器，实现构造器注入。
  3. 使用Patch请求来更新部分资料。
  4. 使用@AuthenticationPrincipal将当前认证主体的身份信息注入到方法参数：当 Spring Security 完成 JWT 解析后，Jwt 对象会被自动绑定到 jwt 参数，无需手动从 SecurityContextHolder 获取。此处用于获取当前登录用户的 JWT。

配置跨域 CorsConfig.java

GET 和 POST 在特定条件下属于浏览器定义的简单请求，不会触发 CORS 预检；

而 PATCH 属于非简单请求，会先发送 OPTIONS 预检请求。如果后端未正确配置 CORS 或未放行 OPTIONS，请求就会被浏览器拦截，接口就无法请求成功
