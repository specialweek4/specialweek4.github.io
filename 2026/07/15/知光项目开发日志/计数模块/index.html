配置

位图分片配置 BitmapShard.java

固定分片大小（32K 位），将用户 ID 映射为分片序号和片内偏移，避免单键膨胀。

计数 Schema 映射及常量定义 CounterSchema.java:

定义计数指标（like/fav）的索引、字段大小和 Schema 长度，提供指标名→索引的映射。

笔记维度 Redis Key 生成工具 CounterKeys.java:

生成 Redis 键：SDS 汇总键(sdskey)、位图分片键(bitmaokey)、聚合增量桶键(aggkey)。

用户维度 Redis （sds）Key 生成工具 UserCounterKeys.java:

生成用户维度的 SDS 键。

计数模块 Kafka 配置 CounterConfig.java

计数事件模型 CounterEvent.java:

计数事件模型（实体类型、ID、指标、用户、delta），由业务操作产生。

计数事件生产者 CounterEventProducer.java:

将 CounterEvent 序列化后发送到 Kafka 主题 counter-events，异步解耦。

计数事件聚合与刷写消费者 CounterAggregationConsumer.java:

  • 消费事件，将 delta 以 HINCRBY 写入 Redis 聚合桶（Hash）。
  • 通过 @Scheduled 定时扫描所有聚合桶，挨个解析key中etype/eid 以定位 SDS key，用 Lua 脚本将桶内增量原子折叠到 SDS 汇总结构，成功后删除桶内字段。

灾难场景下的计数重建消费者 CounterRebuildConsumer.java(按需启用):

从 earliest 位点消费事件，直接调用同一 Lua 脚本将增量折叠到 SDS，用于灾备重建。

笔记维度计数服务实现 CounterServiceImpl.java:

设计思路：

方法toggle

主要负责位图状态切换：仅在状态变化时返回成功，并产出增量事件。当用户点赞，收藏都调用这个方法

  1. 按用户ID映射到 chunk 与分片内 bit 偏移
  2. 执行 TOGGLE_LUA（在CounterServiceImpl定义了） 脚本原子更新位图分片（SETBIT/GETBIT）。仅在状态变化时返回 true
  3. 如果执行脚本成功了即返回true，调用 CounterEventProducer 发布事件。

getCounts

获取实体计数汇总（SDS）

  1. 根据客户传来的参数创建要查询的sdskey
  2. 若缺失或结构异常则触发基于位图的事实重建，并清理对应聚合字段
  • 因为重建需要扫描所有位图分片（BITCOUNT），开销大，因此有三层阀门
    • 退避期检查（inBackoff）：是一种故障保护策略，用于防止在短时间内频繁触发昂贵的重建操作。简单说，就是“这次失败了或太频繁了，就强制等一段时间再试”，来防止大量并发请求可能会同时触发重建。如果该实体已因频繁失败被记录了一个“下次可重建时间”，且当前时间尚未到达，则直接进入if方法体，return 0，完全不尝试重建。
    • 限流检查（allowedByRateLimiter）：使用 Redisson 的 RRateLimiter 令牌桶，限制单位时间内该实体的重建次数。若未获取到令牌 → 调用 escalateBackoff 延长退避时间，返回 0。获取到令牌 → 继续尝试获取分布式锁。
    • 分布式锁（lock.tryLock）
      • 确保同一实体同一时刻只有一个线程/实例执行重建。
      • 获取锁失败 → 同样延长退避时间，返回 0。
      • 获取锁成功 → 持有锁执行真正的重建。
  1. 执行重建：
  • 直接根据位图进行统计
  • 回写sds并清理聚合桶
  1. 如果不需要重键的话就直接读取SDS
  • 通过 CounterSchema.NAME_TO_IDX 获取指标在 SDS 中的索引（位置）。
  • 计算该索引对应的字节偏移量：idx * CounterSchema.FIELD_SIZE（每个字段占 4 字节）。
  • 调用 readInt32BE(raw, off) 从 SDS 原始字节数组中以大端序读取一个 32 位无符号整数，即该指标的实际计数值。
  1. 当重建请求到达且 inBackoff 检查通过（当前不在退避期），进入限流检查 allowedByRateLimiter。
  2. 如果限流器返回 false（即本次不允许重建），则立即调用 escalateBackoff。
  • escalateBackoff 会：
    1. 读取/递增“退避指数”（backoff:sds-rebuild:exp:…）
    2. 根据指数计算延迟时间（指数递增，有上限）
    3. 将 当前时间 + 延迟 写入 backoff:sds-rebuild:until:…，这个值就是可重建时间。

此后，inBackoff 会检查当前时间是否早于该可重建时间，若是则直接拒绝重建。

重建成功后，resetBackoff 会删除退避相关的键，相当于解除禁令。

键本身设置了过期时间（escalateBackoff 中 untilB.set(until, Duration.ofMillis(delay + 1000))），即使没有成功重建，时间到期后也会自动消失，允许后续重试。

allowedByRateLimiter方法

trySetRate：尝试初始化速率配置。如果该限流器已有速率配置（即之前已初始化过），则不会覆盖，返回 false。

脚本配置

  • RateType.OVERALL：限流模式为“全局总量控制”，即所有调用方共享令牌，而非按客户端区分。
  • ratePermits：窗口内的最大许可次数（例如 3 次）。
  • Duration.ofSeconds(rateWindowSeconds)：时间窗口长度（例如 10 秒），合起来表示“每 10 秒最多 3 次”。
