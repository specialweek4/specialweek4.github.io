雀跃JWT双令牌登录改造

发表于2026-08-17|更新于2026-09-01|雀跃

雀跃登录模块改造教程：JWT 双令牌 + Redis 白名单 + Spring Security

1. V2.0登录设计

  1. 用户仍通过雀跃原来的 /user/code 获取手机验证码。
  2. 用户向 /auth/login 提交手机号和验证码。
  3. 后端返回一对 RSA 签名的 JWT：
    • accessToken：15 分钟有效，只用于访问业务接口；
    • refreshToken：7 天有效，只用于换取一对新令牌。
  4. refresh token 的 jti 会存入 Redis 白名单：auth:refresh:{userId}:{jti}。
  5. 访问业务接口时发送 Authorization: Bearer <accessToken>。
  6. Spring Security 自动校验 access token，并把解析后的 JWT 放入安全上下文。
  7. Controller 可以通过 @AuthenticationPrincipal Jwt jwt 获取 JWT，再通过 jwt.getSubject() 取得 userId。
  8. access token 过期后，客户端调用 /auth/token/refresh。旧 refresh token 会从白名单中原子删除，同时生成新的 access/refresh token。
  9. 登出时删除 refresh token 的白名单记录。已经签发的 access token 最多还可使用 15 分钟，这是短 access token 的正常取舍。

但没设计邮箱登录、注册场景、登录审计、验证码限流、密码重置等模块。

一个必须注意的安全点

access token 和 refresh token 都是合法签名的 JWT。如果 Spring Security 只检查签名和过期时间，refresh token 也可能被错误地用于访问业务接口。

所以本文会使用两个解码器：

  • accessJwtDecoder：供 Spring Security 使用，额外要求 token_type=access；
  • refreshJwtDecoder：只在刷新/登出接口内部使用，负责校验签名、过期时间和 issuer，业务代码再要求 token_type=refresh。
