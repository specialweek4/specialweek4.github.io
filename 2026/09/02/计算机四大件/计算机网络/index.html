计算机网络

发表于2026-09-02|更新于2026-09-03|计算机四大件

在浏览器中输入 URL 到页面展示，到底发生了什么？

  1. 在浏览器中输入指定网页的 URL。
  2. 浏览器通过 DNS 协议，获取域名对应的 IP 地址。
  3. 浏览器根据 IP 地址和端口号，向目标服务器发起一个 TCP 连接请求。
  4. 浏览器在 TCP 连接上，向服务器发送一个 HTTP 请求报文，请求获取网页的内容。
  5. 服务器收到 HTTP 请求报文后，处理请求，并返回 HTTP 响应报文给浏览器。
  6. 浏览器接收响应报文，解析 HTML、CSS、JS，进行页面渲染；同时根据页面中的图片、样式、脚本等资源 URL，继续发起请求，直到页面完整显示。
  7. 浏览器在不需要和服务器通信时，可以主动关闭 TCP 连接，或者等待服务器的关闭请求。

OSI模型

对于OSI参考模型，常见的网络设备实现的层次如下，各个节点之间会使用物理传输媒体进行连接：

OSI 参考模型各层的任务与功能如下：

层次 任务 功能
#7 应用层 实现特定网络应用 略
#6 表示层 解决不同主机上信息表示不一致的问题 数据格式转换
#5 会话层 管理进程间会话 会话管理
#4 传输层 实现端到端（进程到进程）通信 复用和分用、差错控制、流量控制、连接管理、可靠传输管理
#3 网络层 把分组从源结点转发到目的结点 路由选择、分组转发、拥塞控制、网际互联、差错控制、流量控制、连接管理、可靠传输管理
#2 数据链路层 确保相邻节点之间的链路逻辑上无差错 差错控制、流量控制
#1 物理层 实现相邻节点之间比特的传输 需定义电路接口参数、信号的含义/电气特性等

第0层为物理传输媒体

不同层次的有些功能虽然一样但是操作针对的单位不同。因为数据链路层的 差错检测 只能保证帧的正确性，所以在网络层也有一个差错检测用来保证 分组 的正确性。连接管理和可靠传输管理同理。

报文段是全局数据，分组、帧和bit是局部数据，由上一句我们可以知道 局部正确 不能=> 全局正确，但是全局正确必然能够 => 局部正确，也就是说我们只需要在传输层对报文段进行检测的话就可以判断传输的数据可不可靠，TCP/IP就把网络层的 差错控制、流量控制、连接管理、可靠传输管理 给砍掉了，只在传输层对收到的报文段进行这些操作。

每一层负责的职能不同：

物理层：负责在物理网络中传输比特流，定义电气、机械等接口标准。

物理传输媒体就比如家里面路由器和电脑主机相连的那个两头带卡扣的线。

外界噪声的干扰可能会导致电信号变形，所以传输数据的时接收方可能会接收到错误的信号，这时候就需要引入数据链路层。

数据链路层：负责数据的封帧和差错检测，以及 MAC 寻址。

任务：是确保相邻节点之间的链路逻辑上无差错。包含以下功能

  1. 差错控制：
  2. 流量控制：协调两个节点的速率

数据链路层以 帧 为单位传输数据

以上三层能保证相邻节点之间逻辑上无差错的传输数据，大多数情况下我们需要经过多个路由器的转发来实现节点之间的数据传输，为了实现数据的存储转发就需要引入网络层。

网络层：负责主导数据的路由与转发工作，通过 IP 地址进行逻辑寻址。

网络层任务:把“分组”从源结点转发到目的结点。包含以下功能

  1. 路由选择:构造并维护路由表,决定分组到达目的节点的最佳路径
  2. 分组转发:将“分组”从合适的端口转发出去
  3. 拥塞控制
  4. 网际互联
  5. 差错检测、流量控制来确保传输的数据报无差错、可靠的传输管理
  6. 连接建立与释放：确保分组的有序、不重复到达
  7. 可靠传输管理：接收方需返回分组确认消息

网络层以 数据报(分组) 为单位传输数据。

网络层实现了主机之间的转发。但是主机中又有很多进程如微信、QQ、QQ音乐等，这时候就需要引入传输层来实现进程到进程之间的通信,因为每个进程都对应以个端口号，所以又称为端到端通信。

传输层：负责端到端的数据传输任务（端：端口 / 进程）。

包含以下功能：

  1. 复用和分用
  2. 差错检测、流量控制来确保传输的数据报无差错、可靠的传输管理
  3. 连接建立与释放：确保报文段的有序、不重复到达
  4. 可靠传输管理：接收方需返回报文段确认消息

传数层的传输单位是报文段，一个报文段可能被分为多个分组，网络层把这些分组发送给目的节点，目的节点接收后由目的节点的网络层拼凑成完整的报文段，交付给目的节点的传输层。

在数据的发送方多个进程可以通过端口号去请求传输层的服务，这是传输层的复用，在数据的接收方传输层又可以通过端口号把对应的数据分派给对应的进程，这是传输层的分用。

会话层：管理进程间会话

主要功能

  1. 会话管理（采用检查点机制，当通信失效的时候从检查点继续恢复通信，类似于文件的断点续传）

表示层：负责把数据转换成兼容另一个系统能识别的格式，包括加密、压缩等。

应用层：负责为各类应用程序提供统一的网络服务接口


数据的发送方从应用层开始向下将一个文件（又称报文），依次拆分成小的数据单位，直到拆分成bit，这个过程为分段，数据接收方，又会依次将数据重组，这个过程为重组。

并且上面的层次会使用下面一层的功能，如应用层会使用表示层的数据格式转换，表示层会使用会话层的会话管理功能。

TCP/IP模型

对于 数据格式转换 和 会话管理 功能，如果传文件两台机器编码格式一样就不需要数据格式转换、在传文件的时网络中断我们选择重新传整个文件也是可以的，所以说这两个功能不是必须的。在TCP/IP中就干掉了表示层和会话层，因为并不是所有的网络应用都需要这两个功能。如果某些应用实在需要可以选择应用层的特定协议来实现。

  • 应用层：为各类网络应用提供统一通信服务接口，让应用程序不用关心底层的网络传输细节。
  • 传输层：实现两台主机上应用程序的 “端到端” 通信，提供通用的数据传输服务
  • 网络层：负责主导数据包的跨网络路由与转发工作，通过 IP 地址实现主机级寻址（IP 协议）
  • 网络接口层：负责数据的封帧、MAC 寻址与差错检测，以及在物理介质中传输比特流8

对于OSI模型对于第一层要干什么，第二层要干什么，分别拥有哪些功能，有哪些特性都需要有清晰明确的规定，也就是说一个厂商在研发物理层和数据链层的设备的时候必须遵循OSI参考模型的规定，TCP/IP 对于网络层以下的层次即网络接口层，只规定了任务(实现相邻节点间的数据传输，为网络层传输“分组”)，但具体怎么传输不做规定。TCP/IP模型比较自由。

TCP/IP模型只在传输层对收到的报文段进行 差错控制、流量控制、连接管理、可靠传输管理，网络层并没有这些检测，所以网络层的数据可能是好的也可能是坏的，不可靠。

这样的好处就是网络核心部分（路由器）的功能相对简单，负载底，造价底。数据传输的正确、可靠由传输层负责,压力给到“网络边缘部分(主机)”

TCP/IP 模型各层的任务与功能如下（记忆口诀：用叔网接）：

层次 任务 功能
#4 应用层 实现特定网络应用 略
#3 传输层 实现端到端（进程到进程）通信 复用和分用、差错控制、流量控制、连接管理、可靠传输管理
#2 网络层 把分组从源结点转发到目的结点 路由选择、分组转发、拥塞控制、网际互联
#1 网络接口层 实现相邻节点之间的数据传输（为网络层传输”分组”） 未规定


在OSI模型中如果在网络层中 差错控制、流量控制、连接管理、可靠传输管理 全部启用就会想传输层提供有连接可靠的服务，如果没有启动那么就和TCP/IP模型一样就是无连接不可靠的服务。在TCP/IP的传输层也有同理的选项。

应用层

网络应用模型：1.C/S模型 2.p2p模型

C/S（客户端/服务器）模型：

  • 由客户端和服务器组成，客户端和服务器不平等，客户端发起请求，服务器集中提供服务。
  • 服务器统一管理数据和资源，便于维护、安全控制和权限管理。
  • 服务器性能和网络状况会影响整体服务，容易形成中心节点或性能瓶颈。
  • 常见于网站、邮箱、数据库等应用。

注:DNS、电子邮件、FTP、Web应用 都是C/S模型

P2P（对等网络）模型：

  • 网络中的每个节点地位平等，既可以请求服务，也可以提供服务。
  • 资源分布在多个节点上，具有较好的扩展性和一定的容错能力。
  • 无需依赖单一中心服务器，可充分利用各节点的带宽和存储资源。
  • 节点管理、安全控制较复杂，节点离线可能影响资源获取。
  • 常见于文件共享、区块链和部分即时通信应用。

DNS(域名系统)

域名就是网址，访问域名本质上是访问该域名对应的主机/路由器，那么像浏览器输入域名主机只知道域名，这里面又没有IP地址，他是怎么访问对应的服务器的呢？这就需要DNS。

DNS（域名系统），就是把域名转换成对应的 IP 地址的协议。你可以把它理解成：网络的电话本。我们记不住每台服务器的 IP 地址，就像记不住所有人的电话号码，只需要记住人的名字（域名），DNS 帮我们查到对应的电话，才能找到目标服务器。

怎么查才能不重名？

如果我们查的名字是这种 咸鱼.咸家村.武汉市.湖北省 具有层次的名字那么发生重名的可能性就会大幅度降低。DNS中也是这样的对域名进行了层次的划分（用 . 分割）从右到左依次是 顶级、二级、三级。

DNS的作用

  1. 方便用户记忆：人们更容易记住 www.baidu.com，很难记住一串数字 IP。
  2. 屏蔽底层复杂地址：让用户用域名访问，不用关心真实 IP 是什么。
  3. 支持服务器切换和迁移：域名不变，背后 IP 可以更换，用户无感知。
  4. 实现负载均衡：同一个域名可以解析到多个 IP，让流量分到多台服务器。

工作过程

  1. 你打开浏览器，输入 www.baidu.com。
  2. 你的电脑发现不知道 IP，发送 DNS 查询请求。
  3. DNS 服务器查询后，返回 IP：110.242.68.3。
  4. 你的电脑拿到 IP，开始连接百度服务器。
  5. 网页加载出来，整个过程你完全不用关心 IP 是多少。
