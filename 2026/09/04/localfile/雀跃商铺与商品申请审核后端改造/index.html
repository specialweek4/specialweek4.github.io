店铺、商品创建

发表于2026-09-04|更新于2026-09-04|local

业务设计

一个用户只能有一个商铺，商铺和商品必须审核，优惠券由商家自主发布：

优惠券默认属于店铺，店铺种的全部商品都可以使用店铺的优惠卷。

用户不能直接写商铺、商品正式表，用户申请创建店铺填写店铺信息，然后这个申请由管理员来审核，管理员确认审核通过后才写入正式表并在客户端显示，用户在店铺中上架商品同理，

tb_voucher 就是优惠券正式表， status ：1 上架、2 下架、3 过期。普通优惠券审核规则为“店主自主发布”，但必须经过店铺归属、金额、有效期等服务端校验。：

用来记录审核的历史数据，只能管理员看。

商铺申请流程

DTO 和接口

方法 路径 权限 说明
POST /merchant/shop-applications 登录用户 提交商铺申请
GET /merchant/shop-applications/mine 登录用户 查看自己的申请
PUT /merchant/shop-applications/{id} 申请人 修改待审核/已拒绝申请
GET /admin/shop-applications 管理员 分页查看申请
PUT /admin/shop-applications/{id}/audit 管理员 通过或拒绝

提交和审核

提交申请只插入 tb_shop_application，不调用 shopService.save()。审核通过时在一个 @Transactional 方法中：

  1. 锁定并确认申请仍为待审核；
  2. 创建正式 tb_shop，初始化 sold/comments/score；
  3. 将生成的 shop.id 写到申请表的 approved_shop_id；
  4. 将申请状态改为已通过；

拒绝时更新为 audit_status = 2 并写理由。。

审核通过后是下架状态，店主手动改为上架

优惠券流程（普通券自主发布，秒杀券审核）

DTO 和接口

优惠券不需要管理员申请审核：

方法 路径 权限 说明
POST /merchant/shops/{shopId}/vouchers 店主 创建普通优惠券（type=0）
PUT /merchant/vouchers/{id}/status 店主 普通优惠券上架/下架
POST /merchant/shops/{shopId}/seckill-voucher-applications 店主 提交秒杀券申请（type=1）
GET /merchant/seckill-voucher-applications/mine 店主 查看秒杀券申请
PUT /merchant/seckill-voucher-applications/{id} 申请人 修改待审核/已拒绝申请
GET /admin/seckill-voucher-applications 管理员 分页查看秒杀券申请
PUT /admin/seckill-voucher-applications/{id}/audit 管理员 通过或拒绝秒杀券

优惠券直接创建

创建前确认店铺存在、已审核通过，且当前用户是店主或管理员；

优惠券无需写申请表或等待管理员，但是要检验金额、折扣比例、有效期、使用规则、重复领取限制，管理员能强制下架。

秒杀卷写入优惠卷表和秒杀卷表。
