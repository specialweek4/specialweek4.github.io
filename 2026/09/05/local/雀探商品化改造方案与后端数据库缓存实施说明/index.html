雀跃热门商品页缓存

发表于2026-09-05|更新于2026-09-05|local

雀探商品化改造方案与后端数据库缓存实施说明

适用项目：D:\queping\queyue_be-main 与 D:\queping\queyue_fe
目标：将雀探前台从“店铺发现”调整为“商品发现”，商品详情可回到店铺，并补齐商品分类与缓存读取策略。本文只提供改造说明，不修改现有源代码和数据库。

一 结论与边界

建议把“雀探”定义为商品发现入口，而不是把店铺领域整体删除。商品是列表和搜索的主体，商品详情页展示商品信息并提供店铺卡片；店铺详情仍保留，作为从商品详情进入店铺、查看店铺地址与优惠券的承载页。

店铺分类是否去掉：建议先去掉雀探前台的店铺分类筛选、分类图标和分类文案，不立即删除 tb_shop.type_id、tb_shop_type 以及商家端店铺类型字段。现有商铺申请审核会校验 typeId，直接删列会影响商家中心、审核和历史数据。待确认店铺分类在业务上完全废弃后，再按迁移阶段删除。

本文假定商品分类是平台级分类（例如咖啡、正餐、甜品），一个商品只有一个主分类。若将来需要多分类，再增加中间表，不要把逗号分隔的分类 ID 放进商品表。

三 目标接口与返回模型

3.1 商品发现接口

新增 GET /product/discover，参数建议为 q、categoryId、current、size、sort。q 搜索商品名称和描述；categoryId 为商品分类；current 从 1 开始；size 限制为 20 或 30；sort 先支持 default、priceAsc、priceDesc、newest。不要复用 /shop/of/name，因为该接口返回 Shop，字段语义和缓存粒度都不匹配。

GET /product/discover?q=拿铁&categoryId=2&current=1&size=20&sort=newest

3.2 商品详情接口

调整 GET /product/{id} 的返回为 ProductDetail。保留商品原有字段，增加 categoryId、categoryName 和 shop 摘要。只允许 status=1 的商品公开访问；若商品下架或店铺 business_status 不为 1，返回“商品不存在或已下架”。管理员/店主后台如需看下架商品，应继续使用受保护的商家接口，不要放宽公开接口。

3.3 分类接口

新增 GET /product/categories，返回启用的商品分类，按 sort、id 排序。分类是公开读多写少数据，可单独缓存。后台应提供分类维护接口，写操作成功后删除分类缓存，并触发商品列表缓存失效或版本递增。

不要保留“只删除旧键、读取却走数据库”的半套实现，否则看起来有缓存失效代码，实际没有缓存命中收益。

7.8 缓存读取检查清单

  • 第一次请求：本地缓存未命中、Redis 未命中、执行一次 Mapper 查询，并回填两级缓存。
  • 第二次请求：同一实例应命中 Caffeine；换实例请求应至少命中 Redis。
  • 并发冷启动：同一个商品或同一个查询键同时请求 20 次，数据库只应出现 1 次回源。
  • 不存在的商品：第一次回源后写入 PRODUCT_CACHE_NULL，两分钟内不重复打数据库。
  • 空分页：缓存正常 JSON，不使用空值标记。
  • 商品审核、上架、下架、编辑：详情键删除，发现页版本号递增，本机发现缓存清空。
  • 分类增删改、启停、排序变化：分类键删除，发现页版本号递增。
  • 店铺关闭或资料修改：店铺缓存和受影响商品详情失效，公开接口重新校验 business_status = 1。
  • Redis 不可用：接口仍能回源 MySQL；日志中能看到 Redis 读写失败指标。

九 迁移与发布顺序

  • 备份数据库，先在测试库执行分类表、字段和索引迁移；检查 NULL 回填数量。

  • 后端先发布兼容版本：能读 category_id，旧商品缺失时显示“其他”；新增分类接口和商品发现接口，但不切换前端入口。

  • 接入商品缓存读取与指标：命中率、回源耗时、空值命中、缓存异常、singleFlight 等待次数。

  • 前端发布商品雀探入口，保留旧 /shops、/shop/:id 路由兼容旧链接。商品详情先完成，再切列表入口，避免列表跳到不存在的页面。

  • 观察至少一个完整缓存 TTL 周期，确认商品审核/上下架/店铺资料修改后不会读到旧数据，再考虑收紧 category_id 为 NOT NULL。

  • 只有确认店铺分类没有业务依赖后，才做删除 type_id 的独立版本迁移。

十 验收清单

类别 验收项
商品发现 空关键词、关键词、分类筛选、排序、分页、无结果、下架商品不可见。
商品详情 能看到商品分类和所属店铺；店铺卡片跳到 /shop/{id}；商品下架或店铺关闭时公开接口拒绝。
商家端 新增/修改商品必须选择有效启用分类；审核拒绝不产生正式商品；审核通过后分类正确复制。
缓存 首次请求回源后命中 Redis；同机热点命中 Caffeine；并发冷启动只有一次回源；空结果不会持续打 DB。
失效 审核通过、上架、下架、商品编辑、分类修改、店铺资料修改后，详情和发现页最终读到新数据。
兼容 旧 /shops 和 /shop/:id 链接可用；商家店铺申请和管理员店铺审核仍能使用 typeId。
安全 公开接口只返回公开 DTO；搜索使用绑定参数；缓存不包含用户态字段、登录信息或可变抢购库存。
