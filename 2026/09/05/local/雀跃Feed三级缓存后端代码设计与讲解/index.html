雀跃 Feed 三级缓存后端代码设计与讲解（知光风格版）

适用范围：仅后端 queyue_be-main。
本次改造目标：把热榜三级缓存的结构与方法名对齐知光（zhiguang_be-main 的
KnowPostFeedServiceImpl / CacheConfig / CacheProperties），同时保留雀跃文档要求
（前 3 页缓存、返回前覆盖实时计数与用户态、点赞不失效缓存、检查点批次后失效一次），
并不做“以后再添加”清单中的内容（热点检测动态 TTL、Redis Pub/Sub、关注 Feed 缓存等）。

代码位置：

  • com.specialweek.cache.config —— CacheConfig（Caffeine bean）、CacheProperties
  • com.specialweek.blog.api.dto —— FeedItemResponse、FeedPageResponse
  • com.specialweek.blog.model —— BlogFeedRow
  • com.specialweek.blog.service(.impl) —— BlogFeedService / BlogFeedServiceImpl
  • SQL src/main/resources/mapper/BlogMapper.xml（selectHotFeed）
  • 入口 com.specialweek.blog.api.BlogController（/blog/hot 与写路径失效钩子）

一、与知光的对齐点（本次改造的核心）

知光 雀跃（本次改造后） 说明
KnowPostFeedService.getPublicFeed(int page, int size, Long currentUserIdNullable) BlogFeedService.getPublicFeed(int page, int size, Long currentUserIdNullable) 方法名一致
KnowPostFeedServiceImpl 单类承载 L2/L1/L0 全流程 BlogFeedServiceImpl 单类承载 含 singleFlight、回源、回填、失效
cacheKey(page, size) 相同，返回 feed:hot:{size}:{page}:v1 知光为 feed:public:{size}:{page}:v{LAYOUT_VER}
assembleFromCache(idsKey, hasMoreKey, page, size) 相同签名 知光第五参 uid 由雀跃移出，避免用户态进缓存
enrich(base, uid) 相同方法名 知光逐条 isLiked/isFaved；雀跃批量 pipeline
writeCaches(...) 相同方法名 先写 ids 列表 + hasMore 软缓存，再写 L0 片段
mapRowsToItems(rows) 相同方法名 知光在映射时逐条填计数；雀跃映射只做基础字段，计数统一在 enrich 批量覆盖
singleFlight（ConcurrentHashMap + synchronized） 相同 防缓存击穿，锁内重查缓存
L2 Caffeine Cache<String, FeedPageResponse>，bean 名 feedPublicCache 相同 由 CacheConfig + CacheProperties 提供
CacheProperties（prefix=cache，嵌套 L2.PublicCfg{ttlSeconds,maxSize}） 相同结构 雀跃默认 5 秒 / 32 条
L1 用 Redis List 存 ID（opsForList.leftPushAll/range） 相同 雀跃键 feed:hot:ids:{page}（知光带 hourSlot，学习版省略）
L0 片段键 feed:item:{id} 相同 值是该条目 JSON（雀跃片段不含计数/用户态）
FeedItemResponse / FeedPageResponse record 相同命名 字段名按雀跃前端契约保留
失效方法 invalidateFeedCache(blogId) / invalidateFeedRanking() 知光为 invalidateCache(id) / invalidateFeedLocalCache(id) + 反向索引监听器

保留的雀跃差异（有意为之）：

  • 缓存页数上限 3（CACHED_PAGES），第 4 页起直查 MySQL 但仍覆盖计数与用户态；
  • 任何返回路径都先 enrich：知光在 L2 命中时直接返回缓存里的计数（≤15 秒旧值），雀跃按自己文档要求每次响应都覆盖实时逻辑计数与用户态；
  • 公共缓存（L0/L2）不含计数与用户态：片段里的 liked/favorites 恒为 0、isLike/faved/followed 恒为 false，返回前统一覆盖（避免知光把某个用户 enrich 后的结果塞进 L2 的串号问题）；
  • 反向索引（feed:public:index:{id}:{hour}）与 FeedCacheInvalidationListener 不引入：失效仍用 invalidateAll + 删键 的简化方案，文档 P0 预留 Pub/Sub；
  • 空页用哨兵 __empty__ 写入 ids 列表短 TTL 缓存（知光未处理空页）。

刻意不引入（“以后再添加”）：

  • HotKeyDetector（热点统计 + 动态延长 TTL）、feed:public:pages 集合、反向索引监听器、getMyPublished（个人 Feed 缓存）、详情缓存。

二、总体架构

核心边界

  • 三级缓存只缓存“大家看到都一样”的稳定内容；计数与个人状态每次返回前覆盖，点赞/收藏不失效任何缓存。
  • 公共缓存中的 FeedItemResponse 恒为 base 形态（计数 0、状态 false），因此无论命中 L2 还是 L0，都必须走 enrich。

6.2 BlogFeedServiceImpl（核心，方法名对齐知光）

blog/service/impl/BlogFeedServiceImpl.java

讲解（对照知光逐段）

  1. getPublicFeed：safeSize/safePage 夹取与知光一致；L2 命中 → enrich → 返回；L1/L0 组装命中 → 回填 L2 → enrich → 返回；都未命中 → singleFlight（ConcurrentHashMap<String,Object> + synchronized，锁内重查缓存）→ 回源 DB（size+1 判 hasMore）→ writeCaches 回填 → L2 回填 base 形态 → enrich 返回。与知光差异：知光把 assembleFromCache 的 enrich 结果直接塞进 L2（会把 A 用户的 liked/faved 缓存在公共键里）；雀跃的 L2 永远存 base，用户态只在返回前计算。
  2. assembleFromCache：先取 ids 列表（Redis List），空列表/空页哨兵处理，multiGet 片段，任一缺失整页回源；hasMore 优先软缓存值、缺失以“满页”兜底 —— 与知光逐行对应。
  3. enrich：雀跃批量版 —— getCountsBatch（pipeline EVALSHA）覆盖计数、getFlagsBatch（pipeline GETBIT）覆盖点赞/收藏态、getBatch 覆盖关注态；计数 Redis 故障降级 MySQL 检查点计数，用户态故障临时 false + 告警。方法名与知光一致，内部由知光的逐条调用升级为批量。
  4. writeCaches：与知光同构（ids 列表 + hasMore 软缓存 + 逐条 L0 片段）；TLL 取雀跃文档值（ids 20±5 秒、片段 10 分钟、hasMore 10 秒）；空页写 __empty__ 哨兵短 TTL 缓存（知光未处理空页）。
  5. mapRowsToItems：只做行映射（计数 0、状态 false），计数填充统一交给 enrich —— 与知光“映射时逐条 getCounts”不同，换取整页一次批量读。
  6. 失效：invalidateFeedCache(blogId) 删该博客 L0 片段 + 清空本机 L2；invalidateFeedRanking() 删前 3 页 ids/hasMore 键 + 清空本机 L2。知光用反向索引 + 监听器精确定位页面，雀跃学习版用全清（P0 预留 Pub/Sub）。

写操作 L0 片段 feed:item:{id} L1 ids 列表 L2 feedPublicCache 计数/用户态

MySQL 检查点批次完成 不删 删除前 3 页 清空 已同步检查点
关注/取消关注 不删 不删 不删 更新 follow 状态键

九、与计数模块的边界

层 负责 不负责
计数模块（counter） Bitmap 事实、聚合桶、SDS、脏版本、检查点、用户态读取 任何页面缓存
三级缓存（BlogFeedServiceImpl） 公共稳定内容的分层缓存、回填、singleFlight、失效 计数与用户态的最终值
enrich 把基础条目 + 实时计数 + 用户态拼成最终条目 缓存读写
Controller 取当前用户、调 getPublicFeed、失效钩子 覆盖细节

一句话总结：类名、方法名、缓存形态（feedPublicCache / Redis List ids / feed:item:{id} 片段 / singleFlight）对齐知光；雀跃保留“任何路径都 enrich、公共缓存不含计数与用户态”两条正确性边界，并把知光逐条读升级为批量 pipeline。
