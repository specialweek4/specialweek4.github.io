写法 作用
rows.stream() 把集合转换成流，组织后续处理步骤
BlogFeedRow::getId 相当于 row -> row.getId()，提取 Map 的键

事务和提交后清理缓存

哪些操作需要放在同一个事务中

商品审核通过涉及创建商品、更新申请、插入审核记录，这些数据库操作应该一起成功或一起回滚。

这是结构示例，doAudit() 表示具体业务处理，并不是要求项目新增这个方法。事务的几个重要规则：

  • 方法通过 Spring 代理调用时事务才会生效，不能指望同一对象内部调用一个带注解的方法就自动开启新事务。
  • 默认对 RuntimeException 和 Error 回滚；需要对受检异常回滚时可配置 rollbackFor = Exception.class。
  • return Result.fail(...) 是正常返回，不会因为 success 为 false 自动回滚。
  • 捕获异常后不再抛出，可能导致事务仍然提交。
  • MySQL 事务不会自动撤销 OSS 复制或普通 Redis 写入。

并发回源与 Redis 锁

本地锁只保护当前进程

缓存未命中时，多个线程可能同时回源。同一个 key 的请求需要进入同一个锁，并在拿到锁后再次检查缓存。

synchronized 只对当前 JVM 有效，多实例部署时不能当作分布式锁。雀跃 Feed 当前使用动态锁 Map；商品详情使用固定锁数组。

使用 ConcurrentHashMap.computeIfAbsent() 获得锁，并不意味着可以随意删除该锁。如果旧锁还有等待线程就移除，后来的请求可能创建新锁，出现同一个 key 两把锁同时工作的情况。这属于动态锁生命周期管理问题。

不可变列表、浅拷贝和缓存对象

List.of() 不允许 null，也不允许增删；stream().toList() 返回不可修改的列表，但可以包含 null。需要修改列表结构时创建 ArrayList。
