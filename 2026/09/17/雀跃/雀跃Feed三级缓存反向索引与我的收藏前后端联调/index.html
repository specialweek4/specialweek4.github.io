雀跃 Feed 三级缓存、反向索引与我的收藏前后端联调

公共 Feed 和已发布博客详情允许匿名请求。收藏、取消收藏、“我的收藏”、草稿、发布和删除都需要 JWT：

前端

公共 Feed

首页展示已发布博客，按发布时间倒序排列。前端使用后端返回的 items 渲染卡片，使用 hasMore 决定是否继续滚动加载。这个功能让首页优先展示新内容，而不是按点赞量形成固定热榜。

点赞和收藏

按钮请求成功后，前端使用响应中的 active 和 count 覆盖当前卡片状态和数字，不在本地盲目加一或减一。按钮请求或动画进行期间会禁止重复点击，用于减少同一用户短时间内重复提交，但它不能替代后端幂等。

我的收藏

个人主页的“我的收藏”按收藏关系最近更新时间展示仍处于发布状态的博客。前端使用普通页码和 hasMore 滚动加载，并按博客 ID 去重。

用户在“我的收藏”页取消收藏后，当前卡片不会立即从数组删除，只把按钮状态改成未收藏。这样当前 offset 列表不会立刻收缩；下次触底时前端会优先补读最后一个已加载页并按 ID 去重，以缓解 offset 前移导致漏读。用户主动刷新收藏列表时从第 1 页重载，已取消的卡片才消失。

内容更新和删除

前端操作成功后更新当前页面显示；缓存定位和失效是后端职责。当前后端反向索引只定向清理本实例 Caffeine 页面，Redis 旧页面仍依赖 60～90 秒 TTL，所以不能把它描述成跨实例、全层级的立即强一致。

实际缓存 Key 和 TTL

位置 Key 当前 TTL/说明
Caffeine feed:public:{size}:{page}:v1 15 秒，单 JVM，不带小时槽
Redis 页面 feed:public:ids:{size}:{hourSlot}:{page} 60～90 秒
Redis hasMore 页面 Key + :hasMore 10～20 秒
Redis 博客片段 feed:item:{blogId} 实际为 60～90 秒，不是源码未使用常量所写的 10 分钟
页面登记表 feed:public:pages:{hourSlot} 60～90 秒，当前只写不读
反向索引 feed:public:index:{blogId}:{hourSlot} 60～90 秒，成员是本地页面 Key

hasMore 先过期时，后端用“当前 ID 数是否等于 page size”推断。刚好满页但已经到底时，可能多请求一个最终空页，这是短 TTL 的可接受退化。

版本化失效

版本不存在时使用 0。第一次真实收藏变化执行 INCR 后，Redis 自动创建版本 Key，值为 1；当前版本 Key没有 TTL。

这不是删除旧缓存，而是用新版本让旧页不可达。旧 Caffeine 页最多约 10 秒自然过期，旧 Redis 普通页 30～49 秒、空页 10～20 秒自然过期。

前端取消收藏后的表现

当前前端不会立刻删除卡片：

  1. 收藏按钮更新为未收藏，数字使用接口响应；
  2. 当前卡片继续留在页面，避免数组收缩后直接按下一 offset 漏掉一条；
  3. 前端记录需要修复的最后已加载页；
  4. 下次触底先重读该页，按博客 ID 去重后追加此前没见过的条目；
  5. 用户主动刷新时从第 1 页重新加载，已取消卡片消失。

这是对 offset 分页位移的前端缓解，不是严格快照分页。若翻页期间其他设备同时大量修改收藏，仍可能发生列表位移；要彻底解决需要后端游标分页或会话快照。

当前收藏缓存细节

  • 本地命中直接返回缓存对象，不重新 enrich，最多可能保留约 10 秒旧计数/状态；
  • Redis 命中会反序列化，再 enrich，然后回填本地缓存；
  • 数据库回源写入 Redis 的是已 enrich 的完整页面；
  • 空页也会缓存，防止无收藏或越界页反复查询；
  • hasMore 在过滤非发布博客前根据收藏关系 ID 计算，所以存在草稿/回收站博客时，一页可能不足 size 但仍返回 hasMore=true。

数据库检查点联调

检查点把 Redis 实时逻辑计数写入 tb_blog.liked、tb_blog.favorites。同步期间如果又发生计数变化，dirty 版本改变，确认脚本不会删掉新的脏标记，下一轮继续同步。

当前任务不会调用 Feed 缓存清理。公共 Feed 正常请求仍读 Redis 实时计数；只有计数服务异常时才使用 MySQL 检查点字段降级。因此检查点的意义是计数持久化、故障恢复基线和降级读取，不负责刷新 Feed 排序或收藏列表。

推荐联调顺序

步骤 操作 预期
1 请求 /blog/hot?current=1 返回完整 FeedPageResponse，首次日志通常为 source=db。
2 立即再次请求 命中 source=local；本地过期后可能命中 source=3tier。
3 查看 Redis 出现页面 ID、hasMore、feed:item、登记表和反向索引。
4 请求下一页 前端使用后端 hasMore，不自行用数组长度代替。
5 把已发布博客保存为草稿或删除 观察两次本地定向失效，并继续观察 Redis TTL 后收敛。
6 收藏、重复收藏、取消收藏 检查关系表 state、changed、Bitmap、聚合桶、dirty 和版本号。
7 请求 /blog/of/myfavs?current=1 检查版本化 Key、收藏顺序、封面、状态和 hasMore。
8 在收藏页取消收藏后继续下滑 当前卡片保留；触底补读上一页且不重复显示博客。
9 主动刷新收藏页 从第 1 页重载，已取消博客不再出现。
10 等待检查点 MySQL 计数字段更新，但 Feed 页面不会因此被全量删除。
